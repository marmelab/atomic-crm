## Live (2026-08-31)

CDK app in `infra/`:

- New VPC (2 AZs, 1 NAT)
- Aurora Serverless v2 Postgres 16.8 (`ardley_crm`), secret generated, deletion protection on
- BFF Lambda in the VPC + HTTP API (`GET /health` open; other routes JWT)
- Cognito app client `ardley-crm-dev` on platform pool `us-east-1_m3IX8Cc9L`
- Seed Lambda applies `docs/schema-direction.sql` + W0–W3 seed on deploy
- S3 + CloudFront SPA; ACM (DNS-validated) + Route53 aliases

Account is **not** hardcoded. `infra/bin/infra.ts` reads `CDK_DEFAULT_ACCOUNT`.

```bash
export CDK_DEFAULT_ACCOUNT=...   # local: same value as the GitHub secret
cd infra
npm install
npx cdk synth
npx cdk deploy ArdleyCrmDevStack
```

GitHub: repository secret `CDK_DEFAULT_ACCOUNT`. Workflow [`.github/workflows/deploy-infra.yml`](../.github/workflows/deploy-infra.yml) passes it as an env var. Deploy still needs `AWS_ROLE_ARN` (OIDC) before Actions can talk to AWS.

SPA env (baked at build):

```
VITE_CRM_API_URL=https://api.crm.dev.ardley.us
VITE_COGNITO_USER_POOL_ID=us-east-1_m3IX8Cc9L
VITE_COGNITO_CLIENT_ID=<stack output CognitoClientId>
VITE_COGNITO_DOMAIN=https://ardley-app-users-dev.auth.us-east-1.amazoncognito.com
```

Tenant still comes from the ID token `custom:customerId` claim (Woodley `100004`, Envoy `100081`). The stub `x-ardley-customer-id` header is local-only.
