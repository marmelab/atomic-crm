# Этап 2. Контрагенты, товары, склад — план и итоги

Источник: TZ.md, раздел 11, этап 2 (разделы 5.1, 5.6, 9). Правила: docs/PRODUCT_RULES.md.

**Готово, когда:** контрагент одновременно клиент и поставщик; польский VAT-номер заполняет название; импортировано 100 товаров.

## Решения (согласовано 2026-11-14, «все да»)

| # | Вопрос | Решение |
|---|---|---|
| 1 | Карточка контрагента | Расширяем существующую «Компанію»: вид (компания / ФОП / физлицо), роли (клиент, поставщик, партнёр — несколько сразу), страна, реквизиты по стране контрагента. В меню — «Контрагенти» |
| 2 | Другие страны | Для стран ЕС без пакета — поле VAT ID; для остальных — налоговый номер текстом |
| 3 | Автозаполнение | VIES через коннектор `/connectors/vies` и серверную функцию; три статуса: дійсний / недійсний / не вдалося перевірити. Украинский реестр — нет (открытый вопрос раздела 13) |
| 4 | Объём 5.1 | Сейчас: роли, реквизиты, VIES, условия (валюта, отсрочка, кредитный лимит), предупреждение о дублях. Позже: прайс-листы и баланс (этапы 4–7), согласия (после юриста), объединение дублей |
| 5 | Товары | Вид (товар / послуга / матеріал), артикул, единица из общего списка, штрихкоды, артикулы поставщиков, цена, ставка ПДВ из пакета страны |
| 6 | Склад | «Основний склад» у каждого бизнеса; приход, списание, перемещение, коригування; проведённое не удаляется — сторно; себестоимость по средней; уходить в минус нельзя |
| 7 | Инвентаризация | С телефона: поиск по штрихкоду (вручную или сканером-клавиатурой); камера — там, где браузер умеет |
| 8 | Импорт CSV | Товары с начальным остатком; роли и реквизиты в импорте контрагентов; тестовый файл на 100 товаров |
| 9 | Меню | Сьогодні · Продажі · Контрагенти · Склад |
| 10 | Права на складе | Проводят владелец, менеджер, комірник; специалист и партнёр смотрят; бухгалтер только читает |

## Сделано (2026-11-14)

### 2.1 Контрагенты
- Колонки `companies`: `kind`, `roles`, `country_code`, `requisites`, `vat_id`, `vat_status`, `vat_checked_at`, `currency`, `payment_terms_days`, `credit_limit` (`supabase/schemas/13_counterparties.sql`, миграция `20261115100000_counterparties.sql`).
- Реквизиты проверяются базой по пакету страны контрагента (общая функция `validated_requisites`, ей же теперь проверяются реквизиты бизнеса). Для страны без пакета реквизиты не принимаются, вместо них VAT ID и налоговый номер.
- `company_duplicates()` ищет контрагента с тем же налоговым номером, IBAN или VAT ID только в своём бизнесе; в форме — жёлтое предупреждение со ссылкой.
- Интерфейс: блок «Контрагент» и «Умови роботи» в форме, бейджи ролей в списке, фильтр «Роль», блок на странице контрагента. Ресурс в интерфейсе теперь называется «Контрагенти».

### 2.2 VIES
- `connectors/types.ts` — единый интерфейс коннектора (fetch и настройки передаются снаружи, секретов внутри нет).
- `connectors/vies` — проверка по REST API Еврокомиссии; разбор адреса на улицу, индекс и город; «не вдалося перевірити» отдельно от «недійсний»; Греция — префикс EL.
- Серверная функция `vies_check` (только для вошедших пользователей; в лог пишется только страна и причина сбоя, без номера).
- Кнопка «Заповнити за VAT» заполняет пустые название и адрес. Проверено на настоящем VIES: NIP 7740001454 → «ORLEN SPÓŁKA AKCYJNA», Płock.

### 2.3–2.4 Товары и склад
- Таблицы `units` (справочник), `products`, `supplier_skus`, `warehouses`, `stock_moves`; представления `products_summary` (остаток и средняя себестоимость) и `stock_levels` (`supabase/schemas/14_products_stock.sql`, миграция `20261115110000_products_stock.sql`).
- Остаток — только сумма движений. Движение нельзя изменить или удалить даже владельцу базы — только `reverse_stock_move()`. Удаление бизнеса целиком по-прежнему работает.
- Запрет минуса проверяется в базе с блокировкой товара, чтобы два одновременных списания не увели остаток ниже нуля.
- Средняя себестоимость — средневзвешенная по приходам, которые не сторнированы.
- Штрихкод уникален в пределах бизнеса; у услуги нет остатков.
- Права: `can_manage_stock()` — владелец, менеджер, комірник.

### 2.5 Инвентаризация
- Страница `/#/inventory` (на телефоне — «Налаштування» → «Склад» → «Інвентаризація»): склад, поиск по штрихкоду, артикулу или названию, повторное сканирование прибавляет 1, кнопки −/+, разница с учётом видна сразу.
- «Провести інвентаризацію» вызывает `post_inventory()`: коригування создаются только для расхождений.
- Камера — через BarcodeDetector браузера, кнопка показывается только там, где он есть.

### 2.6 Импорт CSV
- Импорт товаров (кнопка «Імпорт CSV» в списке товаров): вид, артикул, единица, цена, ставка ПДВ (процент или код), штрихкоды, начальный остаток и его себестоимость → прихід на основной склад.
- Импорт контрагентов читает `kind`, `roles`, `country_code`, `edrpou`, `ipn`, `iban`, `nip`, `regon`, `vat_id`, `currency`, `payment_terms_days`; образец CSV обновлён.
- `test-data/products.csv` — 100 товаров. Импорт через интерфейс: 100 из 100, 88 начальных остатков (у 12 товаров остаток 0).

### 2.7 Меню, переводы, проверка
- Меню: Сьогодні · Продажі · Контрагенти · Склад; во вкладке «Склад» — Товари, Залишки, Рухи товару, Склади, Інвентаризація.
- Все новые тексты — на украинском и английском.
- Автотест `e2e/stage2.spec.ts`. Запуск (нужны `make start` и `npx supabase functions serve`): `PLAYWRIGHT_BASE_URL=http://localhost:5173 npx playwright test e2e/stage2.spec.ts --project=chromium`. Из сессии Claude запуск e2e запрещён проектным хуком, поэтому сценарий пройден вручную во встроенном браузере.

## Известные ограничения и хвосты

- Поиск дублей по телефону и названию, объединение дублей — позже.
- Свои единицы измерения бизнеса — позже.
- Сделки и закупки пока не списывают и не приходуют товар автоматически (этапы 4 и 6).
- Себестоимость считается по всем складам вместе; маржа по продаже — на этапе 4.
- Если встроенный браузер свёрнут, окошко прогресса импорта не закрывается само (особенность библиотеки уведомлений, в видимом окне всё нормально).
