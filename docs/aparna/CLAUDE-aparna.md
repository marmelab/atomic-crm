# Project memory — Aparna's English Coaching CRM

Facts only. Procedures live in skills (`/aparna-loop`). Keep under 80 lines. EDITABLE: when Claude gets something wrong twice, or a human corrects it, add one line under Gotchas or Mistakes Log in the same session (encode-the-fix).

## What this is

- A fork of Atomic CRM, customised for an online English coaching business with global parents (WhatsApp-first).
- Planning pack: `docs/aparna/` — start with `README.md`. Authority: `decisions.md` (accepted) > `MVP.md` (during the MVP track) > `PRD.md` / `ARCHITECTURE.md` / `project_plan.md` / `features.json` > upstream conventions > anything else.
- **Current track: MVP** (`MVP.md`, slices M0–M5). Full-build slices S1–S10 start only after the MVP exit gate, through `TRANSITION.md`.

## Domain names (code ↔ UI)

- `contacts` = Parent. `deals` = Admission. `sales` = Staff user.
- Admission stages: `enquiry`, `trial_booked`, `trial_done`, `payment_pending`, `enrolled`, `lost`.
- MVP: child and fee fields live on `deals` (ADR-A12). Full build adds `students`, `courses`, `batches`, `trials`, `enrolments`, `invoices`, `attendance`, `progress_notes`, `messages`.

## Commands

- Cloud session: `npm ci`, `make typecheck`, `make lint`, `make test` (needs Chromium), `npm run test:unit:functions`, `make start-demo` (UI with fake data).
- Needs Docker (CI or WSL only): `make start`, `npx supabase db diff --local -f <name>`, `npx supabase test db`, Playwright e2e.
- Schema: edit `supabase/schemas/*.sql` AND add the matching hand-written migration in `supabase/migrations/` (ADR-A15). CI proves it applies.

## Rules that are easy to miss

- Only `passes` may change in `docs/aparna/features.json`, and only with pasted green `verify` output (`ci:` = green Check run on the PR).
- MVP: **no Teacher accounts** until F-101 passes (ADR-A14). Only Owner and Counsellor.
- MVP WhatsApp = `wa.me` links from `src/components/atomic-crm/whatsapp/templates.ts`. No WhatsApp API calls in the MVP.
- Every new field or resource needs FakeRest generator updates (Vercel Preview and harness smoke run in demo mode).
- Times: store UTC; display with `formatInZone()`; parents have an IANA `timezone`; batch and staff times are IST.
- Money in paise (`bigint`), never floats.
- Our changelog is `docs/aparna/CHANGELOG.md`. Never edit root `CHANGELOG.md` (regenerated by script).
- Staff are referred to by role (Owner, Counsellor, Teacher) in code, docs and commits — never by personal name.
- One branch + one PR per slice; PR title starts with the slice id, e.g. `[M2]`. Never push to `main`; the human merges.
- Parallel slices touch only the files they own (`MVP.md` §7). Need another slice's file → stop and ask.

## Gotchas

- `deals.lost_reason` was dropped upstream; we re-add it on purpose (ADR-A03).
- Upstream RLS is `using (true)`; any table we touch in the full build gets role policies (ADR-A07).
- `demo/App.tsx` does not use `src/App.tsx`; domain options go in `root/defaultConfiguration.ts` (P-11).
- Cloud sessions have no Docker daemon (P-10); do not try `make start` there.
- First sign-up on a fresh Supabase project becomes the administrator (R-13).
