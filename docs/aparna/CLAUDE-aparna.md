# Project memory — Aparna's English Coaching CRM

Facts only. Procedures live in skills (`/aparna-loop`). Keep under 80 lines. EDITABLE: when Claude gets something wrong twice, or a human corrects it, add one line under Gotchas or Mistakes Log in the same session (encode-the-fix).

## What this is
- A fork of Atomic CRM, customised for an online English coaching business with global parents (WhatsApp-first).
- Planning pack: `docs/aparna/` — start with `README.md`. Order of authority: `decisions.md` (accepted) > `PRD.md` / `ARCHITECTURE.md` / `project_plan.md` / `features.json` > upstream conventions > anything else.

## Domain names (code ↔ UI)
- `contacts` = Parent. `deals` = Admission. `sales` = Staff user (`role`: owner | counsellor | teacher).
- New tables: `students`, `courses`, `batches`, `trials`, `enrolments`, `invoices`, `attendance`, `progress_notes`, `messages`, `provider_events`, `imports`.
- Admission stages: `enquiry`, `trial_booked`, `trial_done`, `payment_pending`, `enrolled`, `lost`.

## Commands
- Run: `make start` (local Supabase + Vite). Demo data: `make start-demo`.
- Verify: `make typecheck`, `make lint`, `make test`, `npm run test:unit:functions`, `npx supabase test db` (pgTAP, files in `supabase/tests/`).
- Schema: edit `supabase/schemas/*.sql`, then `npx supabase db diff --local -f <name>`; never hand-write migrations.

## Rules that are easy to miss
- Only `passes` may change in `docs/aparna/features.json`, and only with pasted green `verify` output.
- Every new resource needs a FakeRest generator (harness smoke runs in demo mode).
- Every new table needs RLS policies for all three roles plus a pgTAP test.
- All automated WhatsApp sends go through `enqueue_message()` → `messages` outbox; never call the WhatsApp API from anywhere else.
- Times: store UTC; display with `formatInZone()`; parents have an IANA `timezone`; batch times are IST.
- Money in paise (`bigint`), never floats.
- Our changelog is `docs/aparna/CHANGELOG.md`. Never edit root `CHANGELOG.md` (regenerated by script).
- Staff are referred to by role (Owner, Counsellor, Teacher) in code, docs and commits — never by personal name.
- Never push to `main`. Work on `slice/S<n>-<slug>` branches; the human merges.

## Gotchas
- `deals.lost_reason` was dropped upstream; we re-add it on purpose (ADR-A03).
- Upstream RLS is `using (true)`; any table we touch must get role policies (ADR-A07).
